# Mission Reflection

## 1. Which cloud infrastructure component do you think is the most important? Why?

I believe compute is one of the most important components of cloud infrastructure because it is responsible for processing tasks and running applications. During the laboratory, I discovered that the KillerCoda server had one virtual CPU core and an Intel Xeon E312xx processor. This made me understand that computing resources are necessary for a server to perform its tasks and support the services running in the environment.

## 2. How does Linux support cloud computing?

Linux supports cloud computing by providing a reliable environment for managing and running server resources. In this laboratory, I used different Linux commands to check the operating system, kernel, CPU, RAM, storage, hostname, and network configuration. Working with these commands helped me understand how cloud servers can be inspected and managed through a terminal.

## 3. Why is technical documentation important before deploying infrastructure?

Technical documentation is important because it helps organize and record the information needed to understand an infrastructure setup. It makes the configuration easier to review and gives engineers a reference when managing or troubleshooting the system. In this laboratory, creating reports and documenting the resources helped me keep track of the server's configuration and infrastructure components.

## 4. What new skills did you learn during this laboratory activity?

I learned how to use basic Linux commands to examine the resources of a virtual server. I learned how to check CPU and memory information, identify disk partitions and mounted filesystems, and examine network interfaces and IP addresses. I also gained experience creating Markdown documentation, comparing cloud platforms, organizing screenshots, and presenting a basic cloud infrastructure design.

## 5. How has your GitHub portfolio improved after completing this mission?

This laboratory helped improve my GitHub portfolio by adding a complete cloud infrastructure project with organized documentation and evidence. I learned how to arrange files and folders properly and document the results of my Linux server investigation. The project also includes information about cloud infrastructure components, cloud provider comparisons, server resources, screenshots, and a cloud architecture diagram. Overall, it gave me a better understanding of how technical work can be documented and presented in a GitHub repository.
